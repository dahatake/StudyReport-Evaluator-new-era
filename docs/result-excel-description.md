# 実行結果Excelの見方（先生向けガイド）

StudyReport Evaluatorが作る結果のExcelファイルに、どんなシートがあり、どの列に何が書かれているかを、ITに詳しくない大学・高校の先生向けに説明します。Excelの基本操作（開く、列を見る、セルに数字を入力する）ができれば読めるように書いています。

> [!WARNING]
> 生成AIが行う評価には正確性が欠ける可能性があるため、必ず自分で責任をもって評点を行ってください。このツールや生成AIは評価結果に対しては一切の責任を負えません

**対象版の注意:** 本書は、本アプリの製品版`0.9.0`の出力に基づきます。`0.9.0`は、前版（`dahatake/StudyReport-Evaluator`）の公開`v0.8.6`の後継として、このリポジトリから配布する版で、まだ公開していません。前版の公開`v0.8.6`・旧`v0.8.1`とは別の版です。特に旧`v0.8.1`とは列の名前や並びが異なる場合があるため、実際のファイルで確かめたうえで使ってください。`0.9.0`のclean-host試験CH-01〜06と本人loginはまだ実施していません。clean-host試験（追加のソフトを入れていない新しいWindows 11 x64での動作確認）は公開の条件で、公開前に実施します。なお、前版の公開`v0.8.6`は、clean-host試験CH-01〜06と本人loginを公開前に実施しないまま公開されました。操作画面の説明は[はじめに](getting-started.md)、点数の考え方は[機能と点数](features.md)を参照してください。

## 1. 結果のExcelとは

アプリは、先生が選んだ回答のExcel（Microsoft FormsやGoogle Formsから書き出したもの）を**そのまま読み取り、元のファイルは変更しません**。評価が終わると、元のファイルの写しに**4枚のシートを付け足した別のExcelファイル**を作ります。これが「結果のExcel」です。

- 元のシート（学生の回答が並んだシート）は、内容もシート名もそのまま残ります。
- 付け足される4枚のシート名は、すべて`Quantification_`で始まります。
- 保存先は、既定では元のExcelと同じ場所の`result`フォルダーです。ファイル名は`eval-年月日-時分.xlsx`の形式です（例: `eval-20260930-1530.xlsx`）。
- 元のExcelに同じ名前のシートがあった場合は、元のシートを変えずに、新しいシート名の後ろに` (2)`を付けます。

このファイルには、学生の回答、評価の指示文、AIの理由などが含まれます。**元の回答Excelと同じか、それ以上に大切なファイル**として扱ってください（[11. 結果を扱うときの注意](#11-結果を扱うときの注意)）。

## 2. まず知っておく言葉

| 言葉 | 意味 |
|---|---|
| 設問 | 回答Excelの1つの質問（1つの列）。学生ごとに回答が入っています。 |
| 評価方法 | 1つの設問をどんな観点で見るかのまとまり。アプリには「知識の網羅」と、先生が指示文を書く「独自」の2種類があります。 |
| 評価項目 | 評価方法の中の具体的な採点の観点。例: 「用語を正しく使っている」。 |
| 固有評価 | 通常の回答とは別に、学生が書いた指示文（プロンプト）などを0〜1で見る追加の評価。使わない設定もできます。 |
| AIの点（`AI_Raw`） | AIが返した素の点数。AIが返すのは、この点数と理由と根拠だけです。 |
| 正規化 | 評価項目ごとに点数の幅（例: 0〜5点、0〜10点）が違っても比べられるように、0〜100に直すこと。 |
| 配点 | 100点満点の内訳。「基礎点」「設問ごとの点」「固有評価の点」を合計してちょうど100になります。 |
| 基礎点 | 回答の内容にかかわらず全員に与える点（既定は60点）。 |
| 類似度 | 学生の回答が、AIが同じ設問に答えて作った参照回答と、文字の並びとしてどれだけ似ているか（0〜1）。 |
| 類似度減点 | 類似度が高いほど引く点。設問の配点 × 類似度 × 減点係数（既定0.1）で求めます。 |
| 数式セル | Excelが計算して出す欄。人が入力した値ではなく、参照元が変わると自動で再計算されます。 |
| 空欄 | 何も入っていないセル。**0点ではありません**。値が決まらなかったという意味です（[7章](#7-空欄0状態コードの読み方)）。 |

**大切な考え方:** AIは「点数の素（`AI_Raw`）・理由・根拠」を返すだけです。基礎点の加算、設問ごとの点、減点、100点満点への調整はすべてExcelの数式が行います。そのため、計算の途中経過をExcel上で確認でき、配点を変えると結果も再計算されます。

## 3. 追加される4枚のシート

| シート名 | ひとことで言うと | 先生が主に使う場面 |
|---|---|---|
| `Quantification_Results` | 学生ごとの採点結果（本体） | 最終点数の確認、理由・根拠の確認、点の手直し |
| `Quantification_References` | 設問ごとの参照回答（AIが作った模範的な回答） | 類似度の比較相手の確認 |
| `Quantification_Config` | 採点の設計図（配点・評価項目・指示文） | 配点や採点基準の確認・変更 |
| `Quantification_Run` | 実行の記録（いつ・どの設定で・何件） | 記録の保管、件数や失敗数の確認 |

途中で中断した場合に作られる`.partial.xlsx`（途中経過のファイル）には、上の4枚ではなく、再開用の`Quantification_Checkpoint`シートが入ります。これは再開のための内部用で、先生が読む必要はありません。完成したファイルには入りません。

## 4. 最初に見る場所: 点数の一覧

先生が最初に見るのは`Quantification_Results`の**いちばん右にある4列**です。

| 列名 | 見方 |
|---|---|
| `Final_Score` | **最終点数**（0〜100点）。成績の目安として見る列です。 |
| `Final_Raw` | 0〜100に収める前の計算結果。マイナスや100超になった場合、この列でわかります。 |
| `Special_Earned` | 固有評価で得た点。固有評価を使わない設定では0です。 |
| `Base_Points` | 基礎点（全員同じ値）。 |

`Final_Score`が空欄の学生は、AIの失敗などで点数が決まらなかった人です。0点ではありません。理由は各列の状態コードで確認できます（[7章](#7-空欄0状態コードの読み方)）。

**行の対応:** `Quantification_Results`の行番号は、元の回答シートの行番号と同じです。たとえば元のシートの5行目の学生の結果は、`Quantification_Results`の5行目にあります。先頭の`SourceRow`列にも、その行番号が数字で書かれています。見出しは、元のシートの見出し行と同じ行番号に置かれます。

## 5. Quantification_Resultsの列の詳しい説明

### 5.1 列が並ぶ順番

左から右へ、次の順に並びます。

1. `SourceRow`（元のシートの行番号）
2. 設問ごとのまとまり（設問の数だけ繰り返し）
   1. 評価方法ごとに、評価項目の列（10列ずつ）と、評価方法の点数の列
   2. 設問の点数の列（4列）
   3. 固有評価の列（項目ごとに6列、項目が1つ以上あるとき設問の固有評価の率を1列）
   4. 類似度の列（6列）
3. 最後に`Base_Points`、`Special_Earned`、`Final_Raw`、`Final_Score`

使わない設問・評価方法・評価項目（設計画面で無効にしたもの）は、列そのものが作られません。

### 5.2 列名の読み方

列名は「**設問のコード.評価方法のコード.評価項目のコード.列の種類**」のように、ピリオドでつないだ形です。たとえば次のようになります。

```text
question-0050af69….evaluator-….criterion-….Normalized
```

コードは、アプリが自動で付ける長い識別用の文字列です。先生が意味を覚える必要はありません。**見るべきなのは、いちばん右の「列の種類」の部分**（`Normalized`、`Reason`など）です。どのコードがどの設問・評価項目かは、`Quantification_Config`の`NodeId`列と`DisplayName`列、`Quantification_References`の`QuestionId`列と`QuestionText`列で確かめられます。列名の左側の部分を見て、同じコードの列が同じ設問・評価項目のものです。

Excelの機能「フィルター」や「検索」で、`.Reason`、`.Final`などの言葉を絞り込むと、目的の列を見つけやすくなります。

### 5.3 評価項目ごとの10列

通常評価では、評価項目1つにつき次の10列が、この順に並びます。「種類」は、人が入れた値のように固定で書かれる**値**か、Excelが計算する**数式**かを示します。

| 列の種類 | 種類 | 意味 |
|---|---|---|
| `.Scorable` | 値 | 採点の対象かどうか。回答があれば`1`、回答が空で採点しなかったときは`0`。 |
| `.AI_Raw` | 値 | AIが付けた素の点数。設計画面で決めた点の幅（例: 0〜5）の中の数。AIが失敗した場合や、回答が空の場合は空欄。 |
| `.Override` | 値 | **先生が手で直した点数**を入れる欄。最初は空欄。入力すると、AIの点の代わりに使われます（[5.9](#59-点を手で直す-override欄)）。 |
| `.Effective_Raw` | 数式 | 実際に採用される点。`Override`があればそれ、なければ`AI_Raw`。幅の外の値は採用されず空欄になります。 |
| `.Normalized` | 数式 | `Effective_Raw`を0〜100に直した点。例: 幅が0〜5で4点なら80。 |
| `.Reason` | 値 | AIがその点を付けた理由（短い文章）。 |
| `.Evidence` | 値 | 理由の根拠になった、学生の回答からの**引用**。回答の文章の一部そのままです。 |
| `.Evidence_Source` | 値 | 根拠がどこにあったか。`PRIMARY_ANSWER`（主な回答）、`SUPPORTING_COLUMN`（補助として選んだ別の列）、`NONE`（根拠なし）のいずれか。 |
| `.Evidence_SourceColumn` | 値 | 根拠がどの列にあったかを示す識別コード。補助の列にあった場合に確認に使います。 |
| `.Status` | 値 | その評価の状態コード。`SUCCESS`なら正常です（[7章](#7-空欄0状態コードの読み方)）。 |

`Evidence`は、AIが「この部分を見て評価した」と示した部分です。**AIが回答をきちんと読んで判断したかを、先生が確かめる手がかり**になります。回答にない文章は根拠として受け付けない仕組みですが、理由の内容が妥当かは先生が判断してください。

### 5.4 評価方法の点数の列

| 列名 | 種類 | 意味 |
|---|---|---|
| `評価方法のコード.Evaluator_Score` | 数式 | 評価方法の点（0〜100）。その評価方法に属する評価項目の`Normalized`を、設定した重みで平均したもの。必要な評価項目の点が揃わない場合は空欄になります。 |

### 5.5 設問の点数の列（4列）

| 列の種類 | 種類 | 意味 |
|---|---|---|
| `.Answer_Present` | 値 | この設問に学生の回答があるか。あれば`1`、空なら`0`。 |
| `.Question_Normalized` | 数式 | 設問の評価点（0〜100）。評価方法の点を重みで平均したもの。回答が空、またはAIの失敗があれば空欄。 |
| `.Question_Rate` | 数式 | 設問の得点率（0〜1）。`Question_Normalized`を100で割った値。**回答が空なら0**、AIが失敗した場合は空欄。 |
| `.Question_Earned` | 数式 | 設問で**実際に得た点**。設問の配点 × `Question_Rate`。例: 配点20点で率が0.8なら16点。 |

### 5.6 固有評価の列

有効な固有評価の項目がある設問にだけ作られます。固有評価の項目1つにつき、次の6列が並びます。列名は「設問のコード.固有評価項目のコード.列の種類」の形です。

| 列の種類 | 種類 | 意味 |
|---|---|---|
| `.Special_AI_Raw` | 値 | AIが付けた点（0〜1）。1に近いほど良い評価です。 |
| `.Special_Reason` | 値 | 理由。 |
| `.Special_Evidence` | 値 | 根拠となる引用。 |
| `.Special_Evidence_Source` | 値 | 根拠の場所（`PRIMARY_ANSWER`、`SUPPORTING_COLUMN`、`NONE`）。 |
| `.Special_Evidence_SourceColumn` | 値 | 根拠のあった列の識別コード。 |
| `.Special_Status` | 値 | 状態コード。固有評価の配点が0のときは`NOT_RUN_ZERO_BUDGET`（AIを使わなかった）。 |

固有評価の項目が1つ以上ある設問には、さらに次の列があります。

| 列名 | 種類 | 意味 |
|---|---|---|
| `設問のコード.Special_Question_Rate` | 数式 | 設問の固有評価の率（0〜1）。その設問の固有評価の点を平均したもの。 |

固有評価の点は、最終的に`Special_Earned`列（[4章](#4-最初に見る場所-点数の一覧)）でまとめられます。

### 5.7 類似度の列（6列）

設問ごとに、次の6列が並びます。類似度は、AIを使わず、アプリの中で文字の並びを比べて求めます。

| 列の種類 | 種類 | 意味 |
|---|---|---|
| `.Similarity_AI_Raw` | 値 | 学生の回答と参照回答の類似度（0〜1）。0は似ていない、1は同じ。列名に`AI`とありますが、実際にはアプリが計算した値です（古い版との互換のためにこの名前を残しています）。回答が空なら0。 |
| `.Similarity_Reason` | 値 | 類似度の値だけを示す機械が作った説明文。学生の回答の文章は含みません。 |
| `.Similarity_Status` | 値 | 状態コード。回答が空なら`EMPTY`。 |
| `.Similarity_Penalty` | 数式 | 類似度による減点。設問の配点 × 類似度 × 減点係数。例: 20 × 0.5 × 0.1 = 1点。 |
| `.Similarity_Peer_Max` | 値 | **同じ設問の他の学生の回答**との類似度のうち、いちばん高い値（0〜1）。情報として付けた列で、点数の計算には使いません。 |
| `.Similarity_Peer_Row` | 値 | 上の`Similarity_Peer_Max`の相手にあたる学生の**元のシートでの行番号**。 |

類似度が高いことは、不正の証明ではありません。たとえば、課題の指示文が具体的なほど、正しい回答どうしが似ることがあります。逆に、類似度が低いことは、回答の質を保証しません。**確認のきっかけ**として使い、判断は先生が行ってください。

### 5.8 いちばん右の4列

`Base_Points`（基礎点）、`Special_Earned`（固有評価で得た点）、`Final_Raw`（0〜100に収める前の合計）、`Final_Score`（最終点数）です。意味は[4章](#4-最初に見る場所-点数の一覧)の表のとおりです。

- 基礎点と`Special_Earned`は、全員に共通の設定をもとにした数式セルです。
- `Final_Raw`と`Final_Score`は、必要な値が1つでも欠けると空欄になります。また、`Quantification_Config`で配点の合計が100でなくなった場合も空欄になります（[9章](#9-quantification_configの列)）。

### 5.9 点を手で直す Override欄

AIの点に納得できない評価項目は、`.Override`の欄に先生が点を入力して直せます。

- 入力できるのは、その評価項目の点の幅（例: 0〜5）の中の数字です。幅の外の値を入れると、Excelがエラーを出して入力できません。
- 回答が空で採点しなかった欄（`.Scorable`が`0`）には入力できません。
- 入力すると、その学生の`Effective_Raw`から`Final_Score`までが**自動で再計算されます**。AIの点（`AI_Raw`）は残るので、AIの点と先生の点を見比べられます。
- 元に戻すには、`Override`を空欄にします。
- 固有評価と類似度には、`Override`の欄がありません。直したい場合は、結果の値そのものを先生の責任で書き換えます。数式のセルを書き換えると、以後は自動で再計算されなくなるので、あらかじめコピーを取っておいてください。

アプリの「結果」画面でも`Override`を入力でき、別名のExcelとして保存できます。手順は[はじめに](getting-started.md)を参照してください。

アプリの「結果」画面の詳細では、Excelを開かなくても、選んだ学生の回答（元のシートの主回答列・補助列）と、評価項目ごとの`AI_Raw`・`Reason`・`Evidence`・`Evidence_Source`、評価項目の説明を並べて確認できます。表示される理由・根拠は、このシートの同じ列の値と同じです。

## 6. 点数が決まるまでの流れと計算例

### 6.1 流れ

1. 設問ごとに、評価項目の点（`AI_Raw`）から`Normalized`（0〜100）を求める。
2. 評価方法の点（`Evaluator_Score`）→ 設問の点（`Question_Normalized`）→ 得点率（`Question_Rate`）と設問の得点（`Question_Earned`）の順に計算する。
3. 固有評価があれば、`Special_Earned`を計算する。
4. 設問ごとに類似度減点（`Similarity_Penalty`）を計算する。
5. 次の式で`Final_Raw`を求め、0〜100に収めたものが`Final_Score`。

```text
Final_Raw   = 基礎点 + 各設問の得点（Question_Earned）の合計 + 固有評価の点（Special_Earned）
              − 各設問の類似度減点（Similarity_Penalty）の合計
Final_Score = Final_Raw を 0 以上 100 以下に収めた値
```

各段階の小数は、`Quantification_Config`の丸め桁数（既定は小数第1位）で四捨五入されます。

### 6.2 計算例

基礎点60、固有評価0、設問が2つで各20点、減点係数0.1の設計で、ある学生（元のシートの5行目）の結果が次のとおりだとします。この数字は説明用の作り話です。

| 設問 | 回答 | `Question_Normalized` | `Question_Rate` | `Question_Earned` | 類似度 | `Similarity_Penalty` |
|---|---|---:|---:|---:|---:|---:|
| 設問1 | あり | 80 | 0.8 | 20 × 0.8 = 16 | 0.5 | 20 × 0.5 × 0.1 = 1 |
| 設問2 | 空 | （空欄） | 0 | 0 | 0 | 0 |

```text
Final_Raw   = 60 + (16 + 0) + 0 − (1 + 0) = 75
Final_Score = 75
```

設問2は空回答なので、AIを使わず、得点は0点として扱います。もしAIの失敗で設問1の`Question_Rate`が空欄になっていたら、`Final_Raw`と`Final_Score`も空欄になり、0点にはなりません。

## 7. 空欄・0・状態コードの読み方

### 7.1 空欄と0の違い

| 見え方 | 意味 | 例 |
|---|---|---|
| 0 | 計算した結果が0。「回答が空だった」など、状態が確定している場合。 | 回答が空の設問の`Question_Earned`は0。 |
| 空欄 | 値が決まらなかった。AIの失敗、中止、未処理など。 | AIが時間切れになった評価項目の`AI_Raw`。 |

空欄を0点として集計しないでください。空欄の学生は、状態コードを確認して、必要ならもう一度実行するか、`Override`で先生が点を入れます。

### 7.2 状態コード

`.Status`、`.Special_Status`、`.Similarity_Status`、および`Quantification_References`の`Status`列には、次のいずれかが入ります。

| 状態コード | 意味 | 対応の目安 |
|---|---|---|
| `SUCCESS` | 正常に評価できた。 | 対応不要。 |
| `EMPTY` | 回答が空だった。AIを使わず、0点として扱った。 | 提出の有無を確認する。 |
| `NOT_RUN_ZERO_BUDGET` | 固有評価の配点が0のため、実行しなかった。 | 対応不要。 |
| `AI_OUTPUT_INVALID` | AIの返答が決められた形式に合わなかった（再試行しても不可）。 | 再実行する。 |
| `AI_TIMEOUT` | AIの返答が時間内に来なかった。 | 再実行する。 |
| `NETWORK_FAILED` | ネットワークの問題で通信できなかった。 | 接続を確認して再実行する。 |
| `RATE_LIMITED` | 短時間に呼び出しすぎて、一時的に制限された。 | 時間を置いて再実行する。 |
| `QUOTA_EXHAUSTED` | 利用枠を使い切った。 | 利用枠を確認する。 |
| `AUTH_REQUIRED` | GitHubへのログインが必要だった。 | ログインして再実行する。 |
| `CANCELLED` | 先生が実行を止めた。 | 再開または再実行する。 |
| `CLEANUP_FAILED` | AIとのやりとりの後片付けに失敗した。 | 再実行する。 |
| `AI_RUNTIME_FAILED` | AIを動かす部品（同梱のCLI）が失敗した。 | [トラブルシューティング](troubleshooting.md)を参照する。 |

状態コードは失敗の原因を示すだけで、点数を0にはしません。失敗時の詳しい対応は[トラブルシューティング](troubleshooting.md)にあります。

## 8. Quantification_Referencesの列

設問ごとに1行あります。参照回答は、先生が選んだAIモデルが設問文だけを見て作った回答で、**同じ実行の中の全員に共通**です。類似度を測るときの比べる相手です。正解や模範解答ではありません。

| 列 | 列名 | 意味 |
|---|---|---|
| A | `QuestionId` | 設問の識別コード。`Quantification_Results`の列名の左側と同じ。 |
| B | `DisplayName` | 設問の表示名（例: 質問 1）。 |
| C | `QuestionText` | 設問の文章。 |
| D | `ModelId` | 参照回答を作ったAIモデルの名前。`auto`は、自動で選ぶ設定。 |
| E | `ReferenceAnswer` | 参照回答の本文。失敗したときは空欄。 |
| F | `Status` | 状態コード。`SUCCESS`以外は、参照回答が作れていません。 |
| G | `GeneratedAtUtc` | 作った日時。世界標準時（UTC）で、日本時間は9時間進めた時刻です。 |
| H | `ReasoningEffort` | AIにどの程度深く考えさせたか。指定がなければ`未指定`。 |

参照回答が作れなかった設問は、回答があってもその設問の類似度と`Final_Score`が空欄になります。

## 9. Quantification_Configの列

採点の設計図です。**どの設問に何点を配り、どの観点で、どんな指示文で評価したか**を記録します。1行目が見出しで、2行目以降が「1行1つの要素」です。列が多いので、要素の種類（A列の`RecordType`）ごとに、使われる列を絞って読みます。

### 9.1 行の種類（A列 `RecordType`）

| `RecordType` | 意味 | 主に使う列 |
|---|---|---|
| `DEFINITION` | 採点設計全体（2行目に1行だけ）。基礎点、固有評価の点、減点係数、合計のチェック。 | `DisplayName`、`SourceSheet`、`HeaderRow`、`FirstDataRow`、`LastDataRow`、`RoundingDigits`、`BasePoints`、`SpecialPoints`、`SimilarityPenaltyWeight`、`AllocationTotal`、`AllocationValid` |
| `CANONICAL_JSON` | 設計全体を、そのまま復元できる形で保存した控え。長い文章は複数行に分割。 | `SnapshotChunk`、`ChunkIndex` |
| `QUESTION` | 設問1つ。 | `NodeId`、`DisplayName`、`ContentText`（設問文）、`PrimarySourceColumn`、`Enabled`、`QuestionPoints` |
| `SUPPORTING_SOURCE` | 設問の補助として使う別の列。 | `ParentNodeId`、`SupportingSourceColumn` |
| `EVALUATOR` | 評価方法1つ。 | `NodeId`、`DisplayName`、`PromptTemplate`、`EvaluatorType`、`Enabled`、`RawWeight`、`EffectiveMinimum`、`EffectiveMaximum` |
| `CRITERION` | 評価項目1つ。 | `NodeId`、`DisplayName`、`ContentText`（観点の説明）、`Enabled`、`RawWeight`、`EffectiveMinimum`、`EffectiveMaximum` |
| `SPECIAL_EVALUATION` | 固有評価の項目1つ。 | `NodeId`、`DisplayName`、`PromptTemplate`、`Enabled`、`SpecialPrimarySourceColumn` |
| `SPECIAL_SUPPORTING_SOURCE` | 固有評価の補助として使う別の列。 | `ParentNodeId`、`SpecialSupportingSourceColumn` |

### 9.2 各列の意味

| 列 | 列名 | 意味 |
|---|---|---|
| A | `RecordType` | 行の種類（上の表）。 |
| B | `Path` | 設計の中での位置を示す内部の表記。読む必要はありません。 |

| H | `PromptTemplate` | AIへ渡した評価の指示文のひな形。 |

| J | `EvaluatorType` | 評価方法の種類。`KNOWLEDGE_COVERAGE`は知識の網羅、`CUSTOM_PROMPT`は先生が指示文を書いた独自の評価。 |

### 9.3 先生が変更できる値

結果のExcelを開いたあとで、次の値を書き換えると、`Quantification_Results`の点数が再計算されます。AIをもう一度使う必要はありません。

- `BasePoints`（基礎点）
- `SpecialPoints`（固有評価の配点）
- `SimilarityPenaltyWeight`（類似度減点の係数）
- `QuestionPoints`（各設問の配点）

**合計を100にしてください。** `AllocationTotal`が100でないと`AllocationValid`が`0`になり、`Final_Score`が空欄になります。たとえば基礎点を60から50に下げたら、どこかの設問の配点を合計で10点増やします。

上の4種類以外の値（重み、点の幅、丸め桁数、指示文など）は、実行時の設計を記録したものです。書き換えると計算結果が変わることがありますが、本書では変更の手順を案内していません。書き換えないことをおすすめします。

**固有評価の配点を後から増やすときの注意:** 実行したときの`SpecialPoints`が0だった場合、固有評価はAIで評価されていません（状態コードは`NOT_RUN_ZERO_BUDGET`）。あとから配点を増やしても、固有評価の点は存在しないため、`Final_Score`は空欄になります。固有評価を使いたい場合は、配点を設定して実行し直してください。

## 10. Quantification_Runの項目

実行の記録です。2列（`Field`と`Value`）で、1行に1項目が並びます。数を数えたり、あとで「いつ、どの設定で実行したか」を確かめたりするときに使います。

| `Field` | 意味 |
|---|---|
| `InputSha256` | 元のExcelの内容から作った確認用の固定長の文字列。同じ元ファイルかどうかの確認に使う。 |
| `InputSizeBytes` | 元のExcelのサイズ（バイト）。 |
| `InputLastWriteTimeUtc` | 元のExcelの最終更新日時（UTC）。 |
| `DefinitionSha256` | 採点設計の確認用の固定長の文字列（`Quantification_Config`のものと同じ）。 |
| `ApplicationIdentity` | 実行したアプリの名前と版。 |
| `CopilotSdkIdentity` | 使ったAI連携部品（GitHub Copilot SDK）の版。 |
| `CopilotCliIdentity` | 使った同梱のAI実行部品（GitHub Copilot CLI）の版。 |
| `ModelIdentity` | 評価に使ったAIモデル。`auto`は自動選択。 |
| `ReasoningEffort` | AIにどの程度深く考えさせたか。指定がなければ`未指定`。 |
| `ContextTier` | 共通設定で選んだ入力の容量区分。`default`は既定、`long-context`は拡張。すべてのAI評価で同じ区分を使う。 |
| `OpenXmlSdkIdentity` | Excelファイルを書く部品の版。 |
| `StartedAtUtc` | 実行を始めた日時（UTC）。日本時間は9時間進めた時刻。 |
| `EndedAtUtc` | 実行を終えた日時（UTC）。 |
| `PlannedEvaluationCount` | 評価する予定だった件数。 |
| `CompletedEvaluationCount` | 評価を終えた件数。成功の件数ではなく、処理が終わった件数。 |
| `ErrorCount` | 失敗した件数。0でなければ、`Quantification_Results`で状態コードが`SUCCESS`以外の欄を確認してください。 |
| `UsageObservedUnitCount` | AIの使用量が取得できた処理の数。 |
| `InputTokenCount` | AIへ送った量の合計（トークン。文章の量を測る単位）。 |
| `OutputTokenCount` | AIが返した量の合計（トークン）。 |
| `ReasoningTokenCount` | AIが考えるのに使った量の合計（トークン）。 |
| `CacheReadTokenCount` | 前回の処理を再利用して読み出した量（トークン）。 |
| `CacheWriteTokenCount` | 再利用のために保存した量（トークン）。 |
| `ConfigSheetName` | 設計図のシートの実際の名前。 |

## 11. 結果を扱うときの注意

- **機密性:** 結果のExcelには、元の回答すべて、評価の指示文、参照回答、AIの理由・根拠が含まれ得ます。メール添付や共有フォルダーへの保存は、元の回答ファイルと同じ配慮で行ってください。詳しくは[データとprivacy](privacy-and-data-handling.md)を参照してください。
- **元のファイル:** アプリは元のExcelを変更しません。既存の結果ファイルの上書きもしません。同じ分に2回実行した場合は、`-02`、`-03`が付いた別名になります。
- **数式を壊さない:** 数式のセルの値を直接書き換えると、以後は自動で再計算されません。点を直すときは、`Override`欄を使ってください。
- **再計算:** Excelで開いたときに、点数が自動で再計算されます。Excel以外の表計算ソフトでは、数式の一部が期待どおりに計算されない可能性があります。
- **AIの点は目安:** AIの点、理由、根拠、類似度は、採点を助ける材料です。**最終的な評点と、その利用の判断は先生が行ってください。** AI品質、教育的妥当性、公平性、法的適合性、不正行為の有無を保証・判定するものではありません。
- **列の名前:** 本書は、製品版`0.9.0`が作るExcelに基づきます。将来の版で列が増えることがあります。
