# ADR-0018: ジョブ単位のAI使用量観測

| 項目 | 内容 |
|---|---|
| 状態 | ADOPTED |
| 決定日 | 2026-09-18 |
| 要求正本 | [requirements-definition.md](../../../docs/requirements-definition.md) §11.9、AC-039、TR-38 |

## Decision

AI使用量の観測を、採点結果とExcel出力から独立した観測台帳として扱う。集計単位は利用者の開始操作ごとに生成するジョブ1件で、保存された行ではなく実際に送信したattemptを数える。

同一attemptの累計は置換で更新し、加算しない。イベント合計とセッション累計、モデル別内訳とセッション総量も加算しない。項目ごとに取得元（イベント／最終RPC／最後の呼び出しのみ）と部分取得を保持し、値の優先順位と取得元を同時に決める。

単位はSDKが報告した原単位のままとする。`nano-AI units`とpremium request消費量を表示・記録し、通貨へ換算しない。換算規則を課金正本で確認できるまで、AIクレジットの数値表示は実装しない。

2026-10-01追補: 要求所有者の依頼（結果画面へのAI Credit表示）を受け、固定SDK `1.0.11`とGitHub Docsの「Usage and billing metrics」が`totalNanoAiu`をAIクレジット費用のnano-AI units表記と定義し、SDKが`NANO_AIU_PER_AIU = 1_000_000_000`を使うことを確認した。上記の「AIクレジットの数値表示は実装しない」をこの追補で置き換え、AIクレジット＝nano-AI units ÷ 1,000,000,000を**表示時だけ**計算する（要求§11.21、FR-CR-01〜04、A-CR-01）。JSONLの記録項目・`UnitPolicy`は変えず、通貨換算と請求確定額としての表示は引き続き行わない。

ジョブログは利用者別ローカル領域のUTF-8 JSON Linesとし、数値・生成ID・閉じたコードだけを書く閉じたDTOを経由する。

## Consequences

- 未取得は0や推定値にせず、明示的な0・未送信・送信状況不明・部分取得と区別する。
- モデル内訳とセッション総量の不一致は不一致のまま記録し、配賦・補正で一致させない。比較は同一の最終RPCで全モデルの費用を取得できた場合に限る。
- コスト取得の失敗・ログ保存の失敗は、評価・再試行・cleanup・checkpointの結果を変えない。
- 既存の`EvaluationTokenUsage`によるExcel集計とcheckpoint schema 1は変更しない。
- 過去ジョブの累計表示、再開前からの通算、ログの再取込UI、予算超過による停止は本決定に含めない。
