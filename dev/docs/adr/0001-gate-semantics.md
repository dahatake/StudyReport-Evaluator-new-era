## 文脈

要求正本v1.1第17節は、同節1〜8を「実装開始前の外部リリースゲート」としていた。要求所有者の訂正を反映したv1.2でもstrict gateは維持するが、特定授業のPrompt/rubric/reason/evidence/missing flags/言語/構造上限は起動後のReportDefinitionへ移し、実装前外部入力から除外した。実装プランv2.1は、要求所有者が次のいずれかを決定するまで`G-01`を完了させない。

1. **厳格 gate**: 第17節1〜8がすべて完了するまで production code を開始しない。
2. **2段階 gate**: 合成データだけを扱う開発開始 gate と、実在学生データを扱う解除 gate に分ける。ただし、先に要求正本を改版し、適用範囲と禁止事項を承認する。

本記録の初版作成時点ではDEC-01の承認証跡がなかった。その後、本セッションの利用者から「全てのタスクの実行を承認」「実装前decision gateは既定案で進める」と明示指示を受領した。DEC-01の既定案は厳格gateであるため、これを正式決定とする。さらに同利用者は、教育内容とreport固有上限は起動後設定であり、設定に教員/製品責任者approvalやlocal launcher identityを要求しないと訂正した。この訂正はADR-0009と要求v1.2へ反映した。他の外部ownerが担う実データの教育評価、個人情報、情報セキュリティ、法務、GitHub組織管理、署名・実機検証を代替しない。

## 暫定統制

要求正本と矛盾しない **厳格 gate を正式適用する**。第17節1〜8および計画上の `GATE-0` がすべて PASS するまで、実装範囲を拡張しない fail-closed 統制とする。

### 許可する作業

- 要求、ADR、schema、preflight、traceability に関する文書作業。
- 個人情報を含まない合成 fixture の仕様策定と生成。
- `spikes/` 配下で行う、採用可否の確認だけを目的とした隔離済み技術検証。ただし、各 spike 自体の計画上の依存を満たしてから実行する。
- 公開された一次資料の調査。秘密、トークン、実在学生データは保存しない。

### 禁止する作業

- `src/` 配下の production code、正式な production/test project、配布物の作成。
- 実在学生の回答、氏名、メールアドレス、学生番号その他の個人情報の取込み、復号、表示、送信、fixture 化。
- 暗号化または権利保護された `sample/` の解除、方式の推測、回答本文や生 metadata の抽出。
- 未承認の選択肢を決定済みとして要求正本へ反映すること。
- 外部承認、実機結果、署名、hash、通信結果、性能値を実測なしに記録すること。

## 現在の判定

**PASS（G-01）**。厳格gate、Phase 0で許可する隔離作業、および禁止する`src/`・配布・実データ処理を確定した。ReportDefinition contract/schemaはPhase 0の許可作業である。`G-RB`、`GATE-0`、Phase 1以降は、それぞれの全依存が実証されるまで進めない。
